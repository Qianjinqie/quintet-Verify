## 결과 우선

📊 **Fable 5 블라인드 평가 결론**

**평가 설정** – Quintet-Verify는 DeepSeek-V4-Flash-0731(활성 파라미터 130억 개인 경량 버전; 법률 문서 작업에는 DeepSeek-V4-Pro-0813 사용)에서 실행되며, 대결 상대는 어떤 프레임워크도 거치지 않고 직접 실행되는 평가 모델 자신(Fable 5)입니다. 평가 모델은 A와 B라는 두 개의 익명 라벨만 봅니다 — 다시 말해, 강력한 모델의 채점 하에서 Quintet-Verify가 구동하는 경량 모델이 F5를 능가했습니다.

Fable 5의 블라인드 평가에서 우리 프로젝트는 전체 9.17/10을 받았고, 대결 상대(Fable 5)는 8.0/10을 받았습니다 – +1.17의 차이입니다.

세 가지 작업 모두에서 승리했습니다:

- 코드 리뷰: 9.2 vs 8.5 (대결 상대 F5는 rpop 메시지 손실, state 필드 덮어쓰기, 예측 가능한 task_id 노출 같은 미묘한 문제를 놓쳤습니다)  
- 기술 방안 평가: 9.5 vs 8.0 (F5는 랭킹 레이어에서 pairwise를 pointwise로 잘못 계산 – 치명적인 오류)  
- 법률 문서 검토: 8.8 vs 7.5 (F5는 구체적인 검증 방안을 제시하지 않았습니다)

참고: 법률 문서 작업은 DeepSeek‑V4‑Pro‑0813을 사용했고, 코드 리뷰와 기술 평가는 DeepSeek‑V4‑Flash‑0731을 사용했습니다. 프레임워크는 표준 모드 – high 강도로 실행되었습니다.

평가자(F5)는 다음과 같이 정성적으로 결론지었습니다:

> 평가된 시스템은 기술적 깊이, 계산 정확성, 리스크 식별, 데이터 뒷받침, 전문적 엄격함의 다섯 차원에서 비교 대상을 능가합니다. 투자 결정, 기술 실사, 프로덕션 배포 전 검토, 컴플라이언스 감사와 같은 고위험 시나리오에 적합합니다.

참고: 실제로 QV는 많은 API 호출을 수행하여 더 높은 비용이 발생합니다 – 돈과 시간을 품질로 교환하는 방식입니다.

## 핵심 제약

- A는 본문을 작성하지 않고, B는 프레임워크를 변경하지 않으며, C는 전문 개정을 제공하지 않고, D는 타인을 대신해 대필하지 않으며, E는 판정을 직접 뒤집지 않습니다.  
- 인지 마커 ✓/?/✗는 비공개 트레이스로만 존재하며 절대 라우팅 결정에 들어가지 않습니다.  
- 환송에는 앵커 좌표가 반드시 포함되어야 합니다; 재작업은 지정된 영역으로 제한됩니다(리플 선언이 변경 범위를 구속합니다).

## 왜 대형 모델 하나만 사용하지 않는가?

단일 모델의 “생성이 곧 확정”이라는 특성이 환각이 종단점까지 직행하는 근본 원인입니다: 스스로 생성하고, 스스로 검토하고, 스스로 확인하므로 감독자와 피감독자가 같은 입장에 서 있습니다. Quintet‑Verify는 이 폐쇄 루프를 서로 권한이 잠긴 5개 역할로 분해합니다 –

견제와 균형은 “자기 규율”에서 “타자에 의한 규율”로 진화합니다: 감독자와 피감독자는 입장을 공유하지 않으며, 모든 환송은 앵커 좌표 안에 구속되므로 재작업이 전체 텍스트가 표류하는 결과를 낳지 않습니다.

## 핵심 기능

- **듀얼 채널 인지 아키텍처**: 공개(라우팅에 보임) 채널과 비공개 Dense Track(✓/?/✗)이 물리적으로 격리되어 있으며, 3계층 보호(구조 / 타입 / 런타임 단언)가 비공개 인지가 절대 라우팅에 들어가지 않음을 보장합니다.  
- **5역할 엄격 견제**: A (아키텍트) · B (실행자) · C (검증자) · D (판사) · E (배심원) – 각자 권한과 금지 영역이 잠겨 있습니다.  
- **3대 철칙(코드로 강제)**: ① 신뢰도 격리 ② 증분 수정(앵커 좌표 + 리플 선언) ③ 서킷 브레이커 발언 금지 명령(max_iterations: 1–10, 기본값 5; D는 발언 금지 명령을 내릴 수 있습니다).  
- **강도 단계**: low / high(기본값) / max; 엄격 모드에서는 결함에 영향 연쇄가 반드시 동반되어야 하며, 신뢰도가 부족하면 D가 통과시키지 않습니다.  
- **빠른 모드**: B/C/D 삼각형만 사용, 개요 없음, 항소 분기 없음 – 간단한 작업과 저비용 시나리오에 적합합니다.  
- **과적합 거버넌스**: C에는 의무 할당량이 없습니다(결함 0개 허용, 단 커버리지 선언 포함 필수); D는 C가 지나치게 트집을 잡는다고 판단하여 재검토로 되돌릴 수 있습니다(최대 2회).  
- **플러그인 메커니즘**: PLUGINS 레지스트리 + flags(기본값은 모두 꺼짐); 선택 사항인 qv_extras.py는 표준화된 pre/post_act_hooks를 통해 마운트할 수 있습니다 – [플러그인](#플러그인) 참조.  
- **커스터마이즈 가능한 워크플로우 (v1.4)**: 워크플로우 정의의 프론트엔드 편집, AE 권한을 상속하는 새 역할 생성, 정적 검증, 역할별 독립 LLM 구성.

## 다른 멀티 에이전트 프레임워크와 어떻게 다른가?

- **AutoGen / CrewAI / MetaGPT**: 모두 멀티 에이전트 협업을 지원하고 모델 무관이지만, 추론 시점 엄격 견제, 비공개 인지 트레이스 감사, 증분 수정(토큰 절약)이라는 세 가지 능력이 없습니다.  
- **Quintet‑Verify**: 멀티 에이전트 협업과 모델 무관성을 지원하는 데 더해, 추가로 다음을 제공합니다:  
  - 추론 시점 엄격 견제(재판 방식의 권한 상호 잠금)  
  - 감사 가능한 비공개 인지 트레이스(Dense Track)  
  - 증분 수정(앵커 좌표 + 리플 선언, 평균 ~80% 컨텍스트 절감)

대부분의 프레임워크는 “AI가 협업하게 하자”를 수행합니다; Quintet‑Verify는 “AI가 서로 견제하게 하자”를 수행합니다 – 전자는 출력 효율을 추구하고, 후자는 결론의 신뢰성을 추구합니다.

## 품질 설명

단일 모델을 직접 사용하는 것과 비교할 때, Quintet‑Verify의 이득은 더 큰 파라미터 수가 아니라 구조적 견제에서 나옵니다:

- **순수 모델과 비교**: 환각이 더 이상 종단점으로 직행하지 않습니다 – 먼저 C의 검토와 D의 판정을 통과해야 하며, 모든 환송은 앵커 좌표 안에 구속됩니다. C의 결함 0개 결론과 D의 과적합 판단은 “트집을 잡기 위해 트집을 잡는” 내부 마찰을 동시에 방지합니다.  
- **순수 J‑Space와 비교**: J‑Space의 밀집 인지 관리는 단일 모델 내부에서 작동합니다; 자기 감독의 천장은 “스스로를 붙잡는 것”입니다. Quintet‑Verify는 ✓/?/✗를 비공개 인지 트레이스로 유지하면서 판정 권한을 독립적인 역할에 위임합니다 – 견제를 자기 규율에서 타자에 의한 규율로 업그레이드합니다.

위 내용은 메커니즘 수준의 정성적 비교입니다; 실제 효과는 일반적으로 베이스 모델보다 훨씬 우수합니다 – 자세한 내용은 결과 우선을 참조하세요.

### 최소 예제 (실제 LLM)

```python
from quintet_verify import (
    DEFAULT_FLAGS,
    LLMConfig,
    PublicState,
    QuintetState,
    build_graph,
    build_llm_agents,
)

# 1. 모델 구성 (OpenAI 호환 엔드포인트; 공유 또는 역할별)
cfg = LLMConfig(
    api_key="sk-...",
    base_url="https://api.deepseek.com/v1",
    model="deepseek-chat",
)
agents = build_llm_agents(cfg)  # 5개 역할 (A, B, C, D, E)를 반환합니다

# 2. 그래프 빌드 및 실행 (interrupt_before_e=False는 E 직전에 사용자 피드백을 위해 일시정지하지 않음을 의미)
graph = build_graph(*agents, interrupt_before_e=False)
final = graph.invoke(
    QuintetState(
        public=PublicState(
            task="Evaluate the feasibility of a technical solution and provide a conclusion.",
            user_satisfied=True,   # 만족 → E가 판정에 동의, 워크플로우 종료
            intensity="high",      # 강도 단계: low / high / max
            flags=dict(DEFAULT_FLAGS),  # 플러그인 스위치, 기본값은 모두 꺼짐
        )
    )
)

# 3. 결과 읽기
pub = final["public"]
print(pub.verdict.approved, pub.verdict.confidence_score)  # D의 판정과 신뢰도
for section in pub.draft.sections:
    print(section.anchor_id, section.content)
```

### LLM 없이 실행하는 오프라인 데모

```python
from quintet_verify import PublicState, QuintetState, build_graph, build_stub_agents

```

## 이론적 기원과 독립성 선언문

### 영감의 출처

Quintet‑Verify는 다음 측면에서 선행 연구로부터 영감을 얻었습니다:

· 인지 마커 기호(✓/?/✗)와 “비공개 인지 트레이스”(Dense Track)라는 명칭: J‑Space Cognition Suite V3.6(doi:10.5281/zenodo.21971181)에서 유래했습니다. 해당 연구는 단일 모델 내부에서 간결한 기호로 인지 상태를 관리하는 방식을 최초로 체계적으로 제안했으며, “자기 성찰 마커”가 추론 품질에 미치는 긍정적 효과를 검증했습니다.
· 다중 역할 재판 방식 견제의 조직 형태: b23.tv/z3C0vVM에서 공개된 Quintet Verification 멀티 모델 토론 시스템에서 영감을 받았으며, 이는 “역할 분리와 이의 제기 절차를 통해 생성 환각을 합의 게임으로 전환한다”는 접근의 실현 가능성을 보여주었습니다.

위 연구들의 원래 기여에 존중과 감사를 표합니다.

### 근본적인 아키텍처 차이

Quintet‑Verify는 기호 명칭은 J‑Space에서, 조직 형태는 Quintet Verification에서 차용했지만, 그 근간을 이루는 인지 아키텍처는 양쪽 모두와 환원 불가능할 정도로 다릅니다. 이러한 차이는 점진적 개선이 아니라 인지 주체, 정보 토폴로지, 통제 성질이라는 세 가지 근본 가정의 재정의입니다.

| 측면 | J‑Space (전역 작업 공간 이론) | Quintet Verification (멀티 모델 토론) | Quintet‑Verify (앵커드 인지 이론) |
|---|---|---|---|
| 인지 주체 | 단일 모델 내부 | 다수의 독립 모델 (상태 없음) | 다수의 독립 에이전트 (각자 비공개 상태 보유) |
| 인지 상태의 담체 | 전역 컨텍스트 윈도우 | 각 모델의 독립 출력 | 공개 공유 상태 + 비공개 트레이스 (물리적 격리) |
| 정보 흐름 | 전역 브로드캐스트 + 경쟁 접근 | 토론식 전체 전송 | 앵커드 참조 (공유 사실은 anchor_id + 체크섬을 통해) |
| 수정 메커니즘 | 전체 재작성 (자기 성찰적 교정에 의존) | 전체 재작성 (토론 교정에 의존) | 증분 수정 (정밀 좌표 + 리플 선언) |
| 통제 성격 | 프롬프트 유도 소프트 제약 | 프롬프트 유도 소프트 제약 | 컴파일 타임 검증 + 라우팅 가드 (하드 제약) |
| 복구 메커니즘 | 텍스트 장부 롤백 | 표준화된 복구 없음 | 원자적 상태 체크포인트 (임의 라운드로 정확히 롤백) |
| 견제와 균형 | 자기 감독 (동일 입장) | 교차 모델 토론 (독립 입장) | 권한 상호 잠금 + 재판 절차 (입장 분리 + 절차적 엄격성) |
| 감사 가능성 | 사고 연쇄 텍스트 (비구조적 롤백) | 토론 텍스트 (비구조적 롤백) | 구조화된 Dense Track 감사 (✓에 대한 추적 가능한 검증 증거와 ✗에 대한 반증 증거) |

### 핵심 차이 요약

· J‑Space는 “한 사람이 어떻게 더 잘 사고하는가”(단일 의식의 깊은 자기 성찰)를 다룹니다;
· Quintet Verification은 “집단이 토론을 통해 어떻게 합의에 도달하는가”(다중 입장을 통한 외부 견제)를 다룹니다;
· Quintet‑Verify는 “독립적인 인지 상태를 가진 에이전트 집단이 엄격한 규칙을 통해 어떻게 검증 가능한 결론으로 수렴하는가”(분산 인지의 헌법적 거버넌스)를 다룹니다.

Quintet‑Verify의 고유한 기여는 “비공개 인지 트레이스(Dense Track)”와 “엄격한 권한 매트릭스”를 최초로 결합한 것으로, 멀티 에이전트 시스템이 개별 추론의 깊이를 유지하면서 감사 가능하고, 추적 가능하며, 강제 종료 가능한 시스템 수준의 신뢰성을 달성하게 합니다.

### 독립성 선언

위의 근본적인 아키텍처 차이에 근거하여, Quintet‑Verify는 다음과 같이 선언합니다:

· 파생 저작물이 아님: Quintet‑Verify는 J‑Space Cognition Suite V3.6의 파생 저작물도 포크도 아닙니다. 두 시스템은 완전히 다른 코드 구현, 인지 토폴로지, 통제 철학을 채택합니다.
· 독립적인 지식 재산: Quintet‑Verify의 모든 코드는 우리 팀이 독자적으로 작성했습니다; J‑Space나 Quintet Verification의 소스 코드, 프롬프트 템플릿, 프로토콜 텍스트를 복사하거나 번역한 바 없습니다.
· 의존성이 아닌 인용: 이 시스템은 J‑Space와 Quintet Verification을 “기술적 의존성”이 아닌 “이론적 참고 자료”로 명시합니다. 이 참고 자료를 제거해도 Quintet‑Verify 핵심 워크플로우의 전체 동작에는 영향이 없습니다.
· 학술적 정직성: 이 선언문은 우리 독창적 기여의 경계를 명확히 하면서 지적 기원을 정확하게 추적하는 것을 목표로 합니다. 분산 인지 아키텍처의 서로 다른 진화 경로를 이해할 수 있도록 독자들이 위 연구들과 이 시스템 간의 비교 연구를 수행하기를 권장합니다.

독자를 위한 권장 사항:

· “단일 모델이 자기 성찰 마커를 통해 추론을 어떻게 개선하는가”에 관심이 있다면, J‑Space Cognition Suite V3.6을 참조하세요.
· “여러 모델이 토론을 통해 어떻게 합의에 도달하는가”에 관심이 있다면, Quintet Verification 시스템을 참조하세요.
· “멀티 에이전트 협업이 엄격한 규칙을 통해 감사 가능하고 검증된 결론을 산출하게 만드는 방법”에 관심이 있다면, Quintet‑Verify를 계속 사용해 주세요.
